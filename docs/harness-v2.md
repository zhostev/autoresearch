# autoresearch harness v2：三夜改动总结

2026-10-20 ~ 10-22。`judge.py` 584 → 1165 行，测试 614 → 2087 行（373 条），新增 `task.py`。
18 个提交，`cfae89a..cf24642`。

## 起点

`autoresearch/flower14` 跑了 15 小时、138 次训练、13 次 accept，**0 个已验证结论**。
报告里写着「纪录可复现」——五次重测证明那个纪录（72 张错）是一次左尾抽样，
同配置的真实均值是 82.8 张。该写的数是 94.47% 正确率，不是 95.19%。

三个根因：

1. `MIN_IMPROVEMENT` 交付值是 `None`，`claim_verdict` 的第 3 条因此让**任何** `claim`
   都返回 `还判不了`。零验证结论不是 agent 偷懒，是这条路被留了个未填的洞。
2. `data_hash()` 哈希的是 `prepare.py` 的文本任务分片，而 flower14 的 `train.py`
   读的是图片目录。该 run 中途把验证集从 98 张改成 1498 张，148 行记录的哈希
   一个字节都没变。**尺子长在被测物身上。**
3. 被 `judge.py` 机械强制的规则全部生效；只写在 `program.md` 里的规则全部失效
   （「不要总从最近的父本出发」被违反 97 次）。**无人值守 15 小时里，劝告的半衰期是零。**

另有一条设计缺口：`compare_seed1` 是精确浮点比较，1/1498 张图就能触发 accept。

## 改动

### 一、把尺子冻住

| 改动 | 解决 |
|---|---|
| 新增 `task.py`：数据根、预算、验证集、指标 | 验证集切分原本住在 agent 可改的 `train.py` |
| `eval_hash` = sha256(task.py + prepare.py + 数据清单) | 取代绑错对象的 `data_hash` |
| 除 `calibrate`/`report` 外所有子命令校验 `eval_hash` | 根因 2 的正面修复 |
| 清单跳过 `.tmp` 与点文件 | 中断下载的残留会无故卡死整夜 |
| `task.should_stop()` 持有终止条件 | agent 原本既定义预算又决定何时不守 |
| judge 读 `task.py` 源码里的 `STEP_BUDGET` 并核对 `num_steps` | 提前退出原本照样打分、被记成有效测量 |

`task.py` 只冻三件事：哪些图属于验证集、标签是什么、错了怎么数。解码、分辨率、
letterbox、翻转 TTA、EMA 全部留在 `train.py`——把它们冻进来等于把搜索成果
写死成协议。

### 二、把判定建立在实测噪声上

```
calibrate    基线跑 5 个种子 → σ，写进 run.json
band         z·σ·√(1/m + 1/n)          两臂样本数都算进去
追加测量      Δ<0 就补跑 seed 2、3，用三次均值重判
claim 门槛    max(band, min_improvement) + 碰运气扣减
```

两次独立标定给出 σ = 3.11 和 3.16 张（1498 张验证集）。**噪声地板是这个任务的
稳定性质，不是偶然。**

一个没预料到的实测结果：把预算从「墙钟 300 秒」改成「固定 10200 步」，
**σ 从 6.2 张降到 3.1 张，方差只剩四分之一，零额外机时**。原来一半的噪声地板
是「300 秒能跑多少步」这件事自己造出来的。同样的问题 nanochat 的调度也有。

**严格性由构造保证**：claim 要求两臂各至少 2 个样本，所以
`√(1/m+1/n) ≤ 1`，band 永远 ≤ `min_improvement`（= z·σ，calibrate 写入），
于是 claim 门槛恒高于 accept 的带宽。碰运气扣减用标定的 σ 而非候选自己的
标准差——错误率离散，两个种子容易撞上同一个数，`σ_cand` 归零会让扣减静默失效。

### 三、把劝告改成强制

| 机制 | 原来 | 现在 |
|---|---|---|
| 父本轮换 | program.md 的一句话，违反 97 次 | 连续 8 次同父本直接拒绝；两夜触发 2 次 |
| 一次只动一个机制 | 三事实约定；`517b245` 名为「半精度」实则同时改了 `IMAGE_SIZE` | `--knobs` 比对 diff 的模块级常量，不符即拒 |
| 必须产出判定 | 「早上」做，从没做过 | accept 自动入队，积压超限拒绝新 trial |
| 「进入名单 ≠ 成立」 | 报告里的措辞 | `REPORT.md` 由 judge 生成，两段物理分开 |
| 拒绝理由 | 27 处沉默的 `return 2` | 每一处都说出是哪条规则 |

### 四、让判定建立在**各自**的噪声上

前三层做完之后跑第三夜，暴露了两个更根本的缺陷。它们不是实现 bug，是统计
设计上的错误假设。

**缺陷 7：σ 不是任务的常数，是配置的属性。**

| 配置 | 样本（1498 张里的错误数） | sd |
|---|---|---|
| 容量基线（5 种子） | 72 74 76 78 80 | 3.16 |
| 可分离（3 种子） | 71 77 72 | 3.21 |
| 线性衰减（3 种子） | 70 74 75 | 2.65 |
| **两者合用（5 种子）** | 65 78 67 87 74 | **8.87** |

两个机制单独用都和基线一样安静，合起来方差翻了一倍多。v2 原本只在基线标定
一次 σ 就拿去判所有机制——于是那个组合在第二、三夜各被放进名单一次。按两臂
各自的噪声重算，它 6.0 张的改进落在 8.6 张的带内，判 `分不开`。

修法是 Welch 式带宽：

```
σ_一臂 = 样本<2 → 标定值；否则 max(观测 sd, 标定值)
SE     = √(σ候选²/m + σ父本²/n)
band   = z · SE
```

取 `max` 是刻意保守：三个样本看着安静往往只是抽样不足，看着吵一定是真吵。

**缺陷 8：多重比较的扣减是固定偏移，使「多测几次」对 claim 毫无用处。**

原来 `claim 门槛 = max(band, min_improvement) + σ·√(2 ln N)`。那个扣减以误差
为单位、不随样本数缩小，`min_improvement` 又固定在 `z·σ`，于是门槛卡死——
一个真实但只有 5 张的改进，测一百次也证不出来。

改成标准误的倍数：

```
claim 门槛 = (z + √(2 ln N)) · SE      ← 随样本数缩小，随机制数增长
accept band =  z           · SE
```

严格性仍由构造保证（`√(2 ln N) > 0`，N 取下限 2），而多测样本真的换来灵敏度：

```
候选 2 父本 2   门槛 11.58 张
候选 3 父本 5   门槛  8.46 张
候选 5 父本 5   门槛  7.32 张
候选10 父本10   门槛  5.18 张
```

`min_improvement` 随之回归 spec 原本的定义——人关心的最小幅度，可以是 0，
不再兼任统计门槛。

### 第三夜的验证

第三夜（4 轮、11 次训练）不为刷分，只为检验修复：

- **缺陷 5 的修复兑现**：claim 用全部 8 个样本，`detail` 写明「候选 3 次 vs
  父本 5 次」。第二夜它只用 4 个。
- **缺陷 6 的修复兑现**：刻意跑一个超预算配置，`should_stop` 从冻结侧在
  544 秒截停，judge 记 `测量失败「只跑了 5612 步，预算 10200 步」`。
- **一个免费的强结论**：第三夜重新标定基线得到 `72 74 76 78 80`，与第二夜
  **逐位相同**——不同分支、不同 `judge.py`、`train.py` 还做过 `should_stop`
  重构。流水线在固定种子+固定步数下完全确定，这也让缺陷 7 的展度证据不含
  测量误差。

## 效果：同一批实验，两套规则

```
flower14    v1 会 accept 5 次 → 名单上 5 条「改进」
            v2 实际 accept 2 次 → 两条都被自己的复核降级
            已验证结论 0

第二夜      v1 会 accept 3 次（71、70、65 张）
            v2 三次均值把前两个拉回 73.3 和 73.0 → 只剩 1 次
            第一夜那个「71 张，全夜最好」被证实是幸运抽样
```

accept 与 claim 的样本用量（以第二夜轮 3 为例，候选 3 个种子、父本 5 个）：

| | 修复前 | 修复后 |
|---|---|---|
| accept | 8 个 | 8 个 |
| claim | **4 个** | **8 个** |

修复前 claim 扔掉手上一半的测量，再用剩下的 4 个推翻 accept 用 8 个得出的结论。

差别不在算法更聪明，在**记账诚实**。

## 代价

```

calibrate    开跑前一次性 25-40 分钟
背压         每 K 次 accept 打断一次搜索

```

## 还没修的

1. **accept 没有多重比较校正。** 它用 `z·SE`，不随已试机制数提高门槛；
   形式校正只在 `claim` 里。追加测量只是方差缩减，不是校正。
2. **`--knobs` 的结构性盲区。** 只覆盖模块级大写常量赋值；新增 `GradScaler`、
   换 `backward` 调用这类改动永远通过 `--knobs ""`。spec 第 7.2 节明确声明了这个
   盲区，并论证过不该用 diff 规模阈值去堵（会误伤，且拆成两次提交就能绕过）。
3. **背压至今未经真实检验。** 三夜共 4 次 accept，队列从未到过上限 3。它的触发
   条件是「积压 3 条未复核的 accept」，而每次 accept 后立刻复核则队列到不了 2。
   这说明它是**兜底机制**——防的是 agent 不自觉复核这种疏忽，而三夜里 agent 都
   自觉了。**不要把「没触发」写成「工作正常」**：它从未在真实疏忽下被检验过。
4. **harness 与实验分支同仓库。** 中途改 `judge.py` 会让 HEAD 脱离父本链，
   必须重开基线。三夜各撞上一次。
5. **σ 的估计仍然薄。** 缺陷 7 的修法用候选那 3 个样本估它自己的噪声，3 个样本
   的 sd 估计很糙；`max(观测, 标定)` 只是把方向压向保守。两个配置方差差异的
   置换检验给出 p=0.068（各 5 个种子），**提示性而非确凿**。

## 附带产物：研究侧结论

瓶颈是**欠拟合 + 浅层空间信息 + 算力天花板**。

- 有效：可分离卷积、线性衰减、容量（到 `WIDTH 56` / `176px` 为止）
- 见顶：`WIDTH 60` 更差、`192px` 以上更差
- 失败：11 个正则化与注意力机制连续无一有效；早降采样惨败（92 张）

最好的配置 `合流` = 可分离残差 + WIDTH 56 + 线性衰减 + 176px，
**70 张错 vs 基线 76 张**（三次均值 vs 五次均值）。

按现在的 σ 和带宽，这个任务在 5 分钟预算下的可搜索空间已基本见底。
要再进一步，该改的是**预算或任务**，不是机制。
