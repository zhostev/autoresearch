# 搜索父本与已验证结论

日期：2026-10-19
状态：设计，待审阅。本文确认前不写实现计划，也不改训练代码。

## 1. 目的

让下一版 `train.py` 在同样 5 分钟里得到更低的 `val_bpb`，并且把「夜里留下的提交」和「可以称为成立的结论」分成两件事。

做法是把实验纪律做进这个仓库自己的循环。不调用 expctl，不运行 Praxist，也不把它们的数据库、命令或调度器拷进来。

## 2. 保留的现有规则

这些规则不变：

- 一次训练的墙钟预算仍是 `prepare.py` 里的 `TIME_BUDGET`（300 秒）。评估仍是 `prepare.evaluate_bpb`。
- 一张 GPU，一次跑一个实验。
- 研究循环开始后，agent 只改 `train.py`。
- agent 不安装新依赖。
- 运行超过 10 分钟就杀掉。
- 实验仍在 `autoresearch/<tag>` 这样的分支上进行。
- `results.tsv` 不提交。

## 3. 不做什么

- 不把 expctl 的命令、账本或实例装进这个仓库。
- 不搬 Praxist 的多 agent、代际关闭、PI、Chair、插件和 `task.yaml`。
- 不设 t 检验的 p 值门槛。两个种子的配对、改进完全相同时判为材料不够，以及下文的碰运气扣减，就是本仓库的统计门。
- `judge.py` 不执行 `git commit`、`git reset` 或 `git checkout`。留下还是退回提交，由 agent 做。
- 不检测 agent 在读完种子之后再次手动调用 `manual_seed`。记录里有当时的完整提交哈希；这是已知残留。

## 4. 搜索

一开始只有基线这一个父本。后来的父本名单最多三个提交。种子 1 更好并且被 `accept` 的提交进入名单；分数持平且更简单的提交可以替换一个已有父本。名单不给这三种情况预留固定位子。名单满了时，淘汰规则会先去掉分数更差、机制又与另一个重复的提交，因此机制不同的提交更不容易被挤掉。agent 下一次改代码前先读名单和实验记录，不要总从最近留下的那个父本出发。

动手前用三个参数写清这次实验：

- `--mechanism`：短机制名，例如 `学习率`。不能含制表符或换行。
- `--expect`：`lower` 或 `higher`。只作记录。比较方向始终是 `val_bpb` 越低越好。
- `--fail`：怎样算这个主意失败，一句话，不能含制表符或换行。

短机制名相同，就当作同一个机制，即使后两句换了说法。

agent 从所选父本的提交开始改 `train.py`，然后提交。新提交的父提交必须是那个父本。接着运行：

```text
uv run judge.py trial --seed 1 --mechanism 学习率 --expect lower --fail 变高或崩溃
```

种子只允许 `1` 和 `2`。种子 1 负责搜索。`trial` 把分数写进记录，不改父本名单。

种子 1 跑完后，agent 自己做 git 决定，再用 `judge.py` 登记名单：

- 记录里的决定是 `好于父本`，而且 agent 认为复杂度值得留下：保持提交，运行 `uv run judge.py accept`。
- 决定是 `持平`，而且代码更简单：保持提交，运行 `uv run judge.py accept --simpler --replace <父本完整哈希>`。这个父本必须已经在名单里。
- 决定是 `差于父本`，或者复杂度不值得：`git reset` 回父本。不运行 `accept`。
- `accept --simpler` 在决定不是 `持平` 时拒绝。分数更差时，不能靠「更简单」进名单。

`好于父本` 指候选的种子 1 `val_bpb` 严格低于父本的种子 1。`持平` 指两者相等。`差于父本` 指候选更高。

`accept` 成功时，这个提交进入名单。进入后如果超过三个，按这个顺序去掉一个：

1. 在机制名出现不止一次的提交里，去掉种子 1 `val_bpb` 最高的。没有这种重复时，去掉全体里种子 1 `val_bpb` 最高的。
2. 分数并列时，不去掉刚进入的提交；在其余并列者中去掉哈希字典序较大的。

如果按这个规则应该去掉的是刚进入的提交，名单保持原样，记录写 `未留下`，细节是 `名单已满`。成功进入时，细节写被去掉的提交哈希；没有去掉则为空。`--simpler` 替换成功时，决定是 `替换父本`，细节写被替换的提交哈希。

种子 2 不在每个实验上跑。一夜搜索只用种子 1。

## 5. 成立

早上只对准备写成「成立」的一两个提交做验证。对基线和候选分别在对应提交上、工作区干净时运行：

```text
uv run judge.py trial --seed 2 --mechanism <与种子1相同的短名> --expect lower --fail <同一句>
```

种子 2 只追加运行记录，不改父本名单。然后在候选提交上运行：

```text
uv run judge.py claim
```

`claim` 不训练。它读取候选 `HEAD` 和它的 git 父提交的种子 1、种子 2。父本名单不因这句话改写。

四个分数都要是训练过程打印出来的。改进定义为父本 `val_bpb` 减候选 `val_bpb`，每个种子各有一个改进，再取平均。平均为正表示候选更好。

按这个顺序写结论：

1. 四行里的 `prepare.py` 哈希或数据身份不完全相同：`还判不了`，细节 `尺子或数据不同`。
2. 四个分数缺任何一个：`还判不了`，细节写明缺哪一个。
3. 最小差距还没写：`还判不了`，细节 `最小差距未写`。
4. 两个种子的改进完全相等，而且这个改进不是 0：`还判不了`，细节 `两次改进没有分开`。
5. 平均改进小于 0：`更差`。
6. 平均改进大于最小差距，并且平均改进减去碰运气扣减之后仍大于最小差距：`成立`。
7. 其余能算出来的情况：`没有更好`。平均改进刚好是 0，也写在这里。

`还判不了` 表示材料不够，不是「没有效果」。

碰运气扣减：

- 设候选两个种子的 `val_bpb` 为样本，`σ` 是它们的样本标准差（除数是 `n - 1`）。两个值相等时 `σ` 是 0。
- `N` 是决定为 `好于父本`、`持平`、`差于父本`、`已记录`、`代码坏了` 或 `测量失败` 的行里，不同短机制名的个数。不算 `基线`。同一个名字出现多少次都算 1。`claim` 行和 `accept` 行不改变 `N`。
- `N <= 1` 时扣减是 0。否则扣减 `= σ × √(2 × ln N)`，自然对数。

最小差距写在 `judge.py` 的 `MIN_IMPROVEMENT`。交付时它的值是 `None`。人在第一次 `claim` 之前把它改成一个正的 `val_bpb` 差值。本文不代填这个数。

## 6. 文件与职责

| 文件 | 谁改 | 作用 |
|---|---|---|
| `program.md` | 人 | 把研究循环改成第 4、5 节的命令。写明 agent 不改 `prepare.py`、`judge.py`、`results.tsv`、`parents.tsv`，不把种子写死，不把「进入名单」说成「成立」。 |
| `prepare.py` | 开跑前改一次，之后冻结 | 增加 `seed_everything()`。评估、数据、`TIME_BUDGET` 仍在这里。 |
| `train.py` | agent | 去掉写死的种子 42，改为调用 `seed_everything()` 并打印种子。 |
| `judge.py` | 人 | 启动训练、解析分数、追加记录、在 `accept` 时改写父本名单、做 `claim`。 |
| `results.tsv` | 只由 `judge.py` 追加 | 全部历史。已在 `.gitignore`。 |
| `parents.tsv` | 只由 `judge.py` 整文件替换 | 当前最多三个父本。加入 `.gitignore`。 |

`judge.py` 先把决定追加到 `results.tsv` 并刷到磁盘，成功之后才替换 `parents.tsv`。替换用临时文件，写完后改名。`accept` 的决定是 `未留下` 时，只追加记录，不改名单。

开跑前，`train.py`、`prepare.py`、`judge.py` 相对 `HEAD` 有未提交改动时，`baseline`、`trial`、`accept`、`claim` 都拒绝执行，并且不追加记录。

同一个完整提交哈希加同一个种子已经有记录时，`trial` 拒绝执行，不追加第二行。

## 7. 记录格式

`results.tsv` 是制表符分隔，有表头。旧的五列（`commit`、`val_bpb`、`memory_gb`、`status`、`description`）停止使用。

列：

```text
commit	parent	mechanism	expect	fail	seed	val_bpb	prepare_hash	data_hash	decision	detail
```

- `commit` 和 `parent` 是完整 git 哈希。基线行的 `parent` 为空。
- `seed` 在 `claim` 行和 `accept` 行写 `*`，因为这两行不是一次训练。
- 崩溃或测量失败时 `val_bpb` 留空，不写 `0`。
- `prepare_hash` 是 `prepare.py` 字节的 sha256。
- `data_hash` 是一份清单的 sha256。清单由三部分按行拼成：`tokenizer.pkl` 的字节大小，验证集分片 `shard_06542.parquet` 的字节大小，以及 `DATA_DIR` 下每个 `.parquet` 的文件名和字节大小（按文件名排序）。不读取训练分片的全部字节。文件缺失时，`trial` 把该行记成 `代码坏了`，细节 `数据身份不可用`。

`trial` 的 `decision` 只用这些词：`基线`、`好于父本`、`持平`、`差于父本`、`已记录`、`代码坏了`、`测量失败`。`基线` 只由 `baseline` 使用。种子 2 的正常完成写 `已记录`。短机制名 `基线` 只允许 `baseline` 使用，`trial` 拒绝这个名字。

`accept` 的 `decision` 只用：`进入名单`、`替换父本`、`未留下`。

`claim` 的 `decision` 只用：`成立`、`还判不了`、`更差`、`没有更好`。

`parents.tsv` 的列：

```text
commit	mechanism	val_bpb	simpler
```

`simpler` 是 `yes` 或 `no`。文件始终只有表头加最多三行数据。

## 8. 命令

`baseline` 只接受 `--seed 1`。它在当前干净的 `HEAD` 上训练，追加一行机制名为 `基线`、决定为 `基线` 的记录，并把这个提交写成名单里的唯一父本，`simpler` 为 `no`。短名 `基线` 不计入 `N`。如果这行记录已经在，而 `parents.tsv` 缺失或没有数据行，`baseline` 不再训练，只按该行补写名单。

`trial` 启动训练时设置环境变量 `AUTORES_SEED`。分数从训练进程的标准输出读取，不从命令行参数读取。`judge.py` 把输出写到 `run.log`。`run.log` 加入 `.gitignore`。

它读取最后一次出现的 `seed:` 行和 `val_bpb:` 行。`seed:` 的值必须等于这次请求的种子。不等或缺失时，决定是 `测量失败`，`val_bpb` 留空，不能 `accept`。进程非零退出、没有 `val_bpb:` 行、或墙钟超过 10 分钟，决定是 `代码坏了`。10 分钟到时，`judge.py` 结束训练进程。

种子 1 的 `trial` 在 git 父提交不在 `parents.tsv` 里时拒绝执行，不训练。种子 2 的 `trial` 在同一提交没有正常完成的种子 1 记录时拒绝执行。种子 2 的短机制名必须和该提交的种子 1 相同，否则拒绝执行。这里说的正常完成，指决定是 `基线`、`好于父本`、`持平` 或 `差于父本`。

`accept` 要求 `HEAD` 有一行种子 1 记录，而且那次决定允许接受，见第 4 节。`HEAD` 没有种子 1 记录时拒绝。

`claim` 使用 `HEAD` 作为候选，使用 `HEAD` 的 git 父提交作为父本。

## 9. 开跑前对训练代码的改动

`prepare.py` 增加：

```python
def seed_everything():
    raw = os.environ.get("AUTORES_SEED")
    if raw is None or raw.strip() == "":
        raise SystemExit("AUTORES_SEED is required")
    seed = int(raw)
    torch.manual_seed(seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed(seed)
    return seed
```

`train.py` 删除现在的 `torch.manual_seed(42)` 和 `torch.cuda.manual_seed(42)`。在同一位置改为：

```python
seed = seed_everything()
print(f"seed: {seed}", flush=True)
```

`seed_everything` 从 `prepare` 导入。现有的 `val_bpb:` 输出保持不变，供 `judge.py` 解析。

## 10. 测试

测试放在 `tests/test_judge.py`，只用标准库，不启动 GPU，不跑 5 分钟训练。

判定函数用记录好的分数直接调用。至少覆盖：

- 候选种子 1 低于、等于、高于父本时，分别得到 `好于父本`、`持平`、`差于父本`。
- 四个分数缺一个、最小差距是 `None`、两臂哈希不同、两个改进都是 `0.010` 时，结论都是 `还判不了`，而且各自的细节不同。
- 平均改进小于 0 时，结论是 `更差`。
- 两个改进都是 0 时，结论是 `没有更好`。
- 手算例子：候选种子是 `0.990` 和 `0.996`，父本种子是 `1.000` 和 `1.002`，另外还有 3 个不同的非基线机制名，因此 `N = 4`。平均改进是 `0.008`。`σ = |0.990 - 0.996| / √2`。扣减 `= σ × √(2 × ln 4)`。最小差距取 `0.001` 时结论是 `没有更好`；最小差距取 `0.0005` 时结论是 `成立`。测试比较结论，并检查扣减与这个式子的差在 `1e-12` 以内。
- `N = 1` 时扣减是 0。
- 接受第 4 个父本时，重复机制里分数更差的被去掉；没有重复机制时，分数最差的被去掉；刚进入的那个正好是应去掉的一个时，名单不变。
- 先写入 `results.tsv` 的测试用一个会在写名单前失败的替身，确认名单文件保持原样。

命令行测试使用临时 git 仓库和假的训练命令，不使用本仓库的 `train.py`：

- `train.py`、`prepare.py` 或 `judge.py` 相对 `HEAD` 有改动时，命令非零退出，且 `results.tsv` 没有新行。
- 同一个提交和种子第二次 `trial`，命令拒绝，记录仍是一行。
- 假训练命令打印的种子与请求不一致时，记录是 `测量失败`，随后的 `accept` 被拒绝。
- 假训练命令超过时限时，进程被结束，记录是 `代码坏了`。测试把时限做成参数，测试里用不足 1 秒的时限，正式运行仍是 10 分钟。

## 11. 做完时的样子

人把 `MIN_IMPROVEMENT` 写成自己的正数之前，任何 `claim` 都得到 `还判不了`。

agent 按 `program.md` 可以完成：建立基线、用种子 1 搜索、用 `accept` 更新最多三个父本、对选定提交补种子 2、得到 `成立`、`还判不了`、`更差` 或 `没有更好` 之一。agent 不需要手改两个表。

父本名单上的提交是搜索结果。只有 `claim` 写出 `成立` 的那一行，才是已验证结论。
